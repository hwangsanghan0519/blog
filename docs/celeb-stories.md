# 셀럽스토리 운영

홈의 바이럴 베스트 바로 아래에 셀럽 프로필, 팔로워 수, Instagram 프로필 바로가기를 표시합니다. 테이프로 붙인 듯한 직사각형 포토 카드를 가로로 배치하고, 각 사진에 흐르는 Instagram 색상 그라데이션 테두리를 표시합니다. 이 테두리는 장식이며 실제 스토리 게시 여부를 나타내지 않습니다. 게시물 피드와 스토리 상태는 조회하지 않습니다.

## 실제 연동 설정

### 2026-09-28 운영 장애 확인

- 복구 전 운영 함수의 수영 조회 결과는 `state: unconfigured`, `followers: null`이었으며, 배포 서버의 Instagram 환경변수가 누락돼 있었습니다. 로컬 `.env.local`은 Git에서 제외되며 배포 서버에 자동으로 전달되지 않습니다.
- 로컬에 저장된 기존 토큰도 Meta에서 오류 190(세션 만료)을 반환했습니다. 기존 토큰을 그대로 운영 서버에 옮겨도 복구되지 않습니다.
- Meta에서 유효한 토큰을 발급·검증한 뒤 Netlify의 해당 프로젝트 환경변수에 `INSTAGRAM_ACCESS_TOKEN`, `INSTAGRAM_USER_ID`, `INSTAGRAM_GRAPH_VERSION=v26.0`을 설정합니다. 운영(Production) 컨텍스트와 Functions 범위에 적용하고 재배포해야 합니다. 토큰은 채팅·소스·공개 `VITE_` 변수에 넣지 않습니다.
- 배포 후 `npm run check:instagram`으로 운영 서버의 모든 등록 계정을 점검합니다. 다른 배포 주소는 `npm run check:instagram -- https://배포주소`로 확인합니다. 미설정·조회 실패·팔로워 누락은 종료 코드 1로 보고하며, 수치를 임의로 보충하지 않습니다.
- 인증 갱신 후 검증한 토큰을 로컬 `.env.local`과 Netlify Production 비밀변수에 저장하고 개발 서버 재시작·운영 재배포를 완료했습니다. 운영 점검에서 수영 7,377,654명, 채령 4,995,152명, 예지 5,809,766명 조회가 성공했고 로컬 화면에서도 숫자 표시를 확인했습니다. 이는 점검 시점의 값이며 고정 수치가 아닙니다.
- **새 토큰도 디버거에서 약 1시간 이내 만료로 확인됐습니다. 현재 복구는 단기 토큰을 사용합니다. 장기 토큰 확장과 확장 토큰의 로컬·운영 교체, 재배포 후 재검증이 남아 있습니다. UI 수정만으로 팔로워 API 인증이 복구되지는 않습니다.**

2026-09-26에 `Powerpuff Celeb Story` 앱의 사용자 토큰에서 `instagram_basic`, `instagram_manage_insights`, `pages_read_engagement`, `pages_show_list` 승인과 실제 Business Discovery 조회를 확인했습니다. 관리 페이지의 `instagram_business_account`를 직접 조회해 운영 계정 ID를 확인했고, 비밀값을 Git에서 제외되는 `.env.local`에 저장해 로컬 서버에 연결했습니다. `me/accounts`는 빈 목록을 반환했지만 페이지 직접 조회와 셀럽 조회는 정상 작동했습니다.

수영·채령·예지는 실제 팔로워 수와 프로필 사진이 반환됩니다. 한소희(`xeesoxee`)·윈터(`imwinter`)는 현재 Meta에서 `Invalid user id`(110)를 반환합니다. 이 응답만으로 정확한 원인을 단정하지 않으며, 해당 프로필의 숫자는 `집계 중`로 표시하고 Instagram 링크는 유지합니다. 현재 토큰은 단기 사용자 토큰입니다. **Netlify 환경변수 등록·운영 배포는 완료했으나 장기 운영용 토큰 확장은 아직 완료되지 않았습니다.**

1. Meta for Developers 등록을 마칩니다. 약관 동의와 본인 확인은 계정 소유자의 확인이 필요합니다.
2. Instagram API with Facebook Login 앱과 Facebook 페이지에 연결된 운영용 Instagram 프로페셔널 계정을 준비합니다.
3. Business Discovery에 필요한 Facebook 사용자 액세스 토큰 권한은 `instagram_basic`, `instagram_manage_insights`, `pages_read_engagement`입니다. 페이지 목록 조회에는 `pages_show_list`가 필요할 수 있습니다. 비즈니스 관리자를 통해 페이지 역할을 받은 경우 추가 권한 요구 사항을 아래 공식 문서에서 확인합니다. 앱 접근 수준에 따라 앱 검수가 필요합니다.
4. Netlify 함수 환경변수에 `INSTAGRAM_ACCESS_TOKEN`, `INSTAGRAM_USER_ID`(운영 계정의 Instagram 사용자 ID), `INSTAGRAM_GRAPH_VERSION=v26.0`을 등록하고 배포합니다. 토큰을 소스·브라우저·공개 저장소에 넣지 않습니다. 앱 ID와 Instagram 사용자 ID는 다릅니다.
5. `/.netlify/functions/celeb-stories?username=sooyoungchoi` 응답에서 `state: ready`, `followers`, `fetchedAt`을 확인합니다. 팔로워 수가 반환되지 않으면 `null`로 유지하며 0으로 표시하지 않습니다.

로컬에서는 같은 값을 `.env.local`에 지정하고 `npm run dev`를 실행합니다. Vite의 개발 서버 전용 미들웨어가 같은 Netlify 함수를 실행합니다. 토큰 변경 후 서버를 재시작합니다. 개발 미들웨어는 환경값을 함수에 명시적으로 전달하며 `process.env`를 덮어쓰지 않아 이전 토큰이 재시작 후에도 우선 적용되던 문제를 방지합니다.

## 셀럽 계정

기본 대상은 기존 운영 상품의 프로필 출처에서 확인한 수영(`sooyoungchoi`), 한소희(`xeesoxee`), 채령(`chaerrry0`), 윈터(`imwinter`), 예지(`yezyizhere`)입니다. 계정별 실제 조회 결과는 위 연결 상태를 참고합니다.

관리자 상품 편집 화면의 **셀럽스토리 관리**에서 이름과 인스타 아이디 또는 프로필 주소를 등록하고 **변경 적용**을 누릅니다. 순서 변경·삭제를 지원하며, 상단의 **서버 저장됨** 상태로 저장 완료를 확인합니다. 목록은 기존 콘텐츠 저장소와 공개 요약에 함께 보관됩니다. 이름은 기존 셀럽 카테고리와 맞추면 기존 사진을 대체 이미지로 쓸 수 있습니다. 전체 삭제 시 콘텐츠를 숨깁니다.

관리자 목록이 아직 저장되지 않았다면 `INSTAGRAM_CELEB_ACCOUNTS`의 아래 JSON 배열이 서버 기본 목록을 대체합니다. `name`은 사이트의 셀럽 카테고리 이름과 일치해야 합니다. 중복·잘못된 사용자명·30개를 넘는 목록은 거부합니다.

```json
[
  { "name": "수영", "username": "sooyoungchoi" },
  { "name": "한소희", "username": "xeesoxee" }
]
```

등록된 계정만 서버에서 조회할 수 있습니다. 첫 요청 중에는 `불러오는 중`, 미연결·조회 실패 상태에서는 `집계 중`를 표시합니다. 확인된 사용자명의 Instagram 프로필 바로가기는 인증 전에도 작동합니다.

## 갱신과 장애

- 브라우저는 보이는 동안 1분마다 확인하고, 서버/CDN은 계정별 15분 캐시를 사용합니다. 즉시 푸시 방식이 아니며 API 반환 지연이 있을 수 있습니다.
- `username`, `profile_picture_url`, `followers_count`만 요청합니다. 게시물·스토리를 수집하지 않습니다.
- 통신 실패와 502/503/504 응답은 한 번 재시도합니다. 잘못된 계정·인증 실패는 반복 호출하지 않습니다. 브라우저는 갱신 중 숫자를 비우지 않고, 실패가 반복돼도 계정별 마지막 정상 팔로워 수와 프로필 사진을 시간 제한 없이 유지합니다. 이 값은 React 상태와 브라우저 localStorage에 보관해 새로고침 후에도 복원하며, 정상 응답이 다시 오면 새 수치로 갱신됩니다. 지난 수치는 점과 마지막 확인 시각을 포함한 툴팁으로 구분합니다. 브라우저 저장소를 지우거나 저장이 차단된 환경에서는 서버 저장 값이 필요합니다. 처음부터 성공 수치가 없는 계정에는 숫자를 만들지 않고 `집계 중`을 표시합니다. 누락·음수·비정상 숫자 응답도 정상 수치를 덮어쓰지 않습니다.
- 서버는 마지막 정상 데이터를 기간 제한 없이 `stale`로 반환하며 원래 확인 시각을 유지합니다. Supabase 서버 환경변수와 기존 `blog-assets` 버킷이 준비된 환경에서는 `instagram-profiles/{username}.json`에 공개 프로필 값만 저장해 서버 재시작·배포·토큰 교체 후에도 복원합니다. 실패 응답은 저장된 수치를 덮어쓰지 않습니다. 개발 서버는 `.cache/instagram-profiles`에 원자적으로 저장해 재시작 후에도 복원합니다. 운영 저장소 미설정·장애 시에는 해당 실행 인스턴스의 메모리 캐시와 방문자 브라우저의 저장 값만 사용할 수 있습니다. 최초 성공 응답이 없으면 숫자를 만들어 표시하지 않습니다.
- 인증·권한·호출 한도 오류는 토큰을 공유하는 계정 전체에 재시도 대기를 적용합니다. 브라우저는 인증 장애 중에도 계정마다 한 번씩 서버를 조회해 각 계정의 저장 값을 복원하고, 이후 5분 대기 종료까지 같은 계정의 반복 요청을 억제합니다. `stale`과 실패 응답은 CDN에 캐시하지 않습니다.
- 토큰 만료·권한 철회 시 조회가 중단됩니다. Meta 도구에서 권한·유효기간을 점검하고 갱신한 토큰으로 서버 환경변수를 교체합니다.
- 공개 응답에 토큰·API 원본 오류·개인 메시지·비공개 게시물을 포함하지 않습니다.

## 검증

`npm run check`에서 134개 테스트·린트·빌드를 통과했습니다. `tests/celeb-stories-api.test.ts`는 미설정, 정상 응답, 인증 실패, 계정 불일치, 게시물 미요청, 캐시·동시 요청·장애 복구를 검증합니다. 실제 토큰을 연결한 로컬 함수에서 등록된 5개 계정의 응답도 확인했습니다.

## 반응형 화면

- PC는 비대칭 타이틀을 왼쪽에, 살짝 기울어진 포토 카드를 오른쪽에 놓습니다. 크림 종이·라일락 테이프·스티커 타이틀로 구성하고 사진 안쪽에 흰 여백과 얇은 Instagram 그라데이션 테두리를 둡니다. 제목과 테두리는 실제 방송·스토리 게시 여부를 의미하지 않습니다.
- 팔로워 수는 `95만`, `737.8만`처럼 숫자를 굵게, 단위를 작게 표시합니다. 모바일은 타이틀을 한 줄로 압축하고 78px 포토 카드와 75px 사진 영역을 가로로 넘깁니다. 인접 콘텐츠와의 외부 간격은 8px입니다.
- 모바일 셀럽 랭킹은 찾기 버튼 위 왕관 버튼으로 엽니다. 배경 딤드, 포커스 제한, 닫기 버튼을 갖춘 투표 창에서 기존 투표 API와 상태를 공유합니다. PC는 본문 랭킹을 유지합니다.

공식 사양(2026-09-26 확인): [Business Discovery](https://developers.facebook.com/documentation/instagram-platform/instagram-api-with-facebook-login/business-discovery), [권한 및 참조](https://developers.facebook.com/documentation/instagram-platform/instagram-graph-api/reference/ig-user/business_discovery).

- 타이틀의 글자 웨이브, 사진 광택, 그라데이션 테두리 흐름, 포토 카드의 부유 효과, 하트·별 입자가 차분한 라일락·크림 바탕에서 동작합니다. 스티커 형태의 타이틀과 점선 구분선을 사용하며, 강한 네온 색상은 사용하지 않습니다. 프로필에 마우스나 키보드 포커스를 올리면 사진과 이동 화살표가 반응합니다.
- PC에서는 섹션 첫 진입에 프로필이 순서대로 나타나고 화면 밖에서 모션을 멈춥니다. 모바일·터치 기기는 화면 감지 결과와 관계없이 CSS로 모션을 시작해, IntersectionObserver 결과가 갱신되지 않아도 정지하지 않습니다. 숨겨진 탭과 사용자가 누른 일시정지는 별도로 처리합니다. 헤더의 일시정지 버튼으로 모션을 제어할 수 있으며, PC의 모션 줄이기 설정에서는 애니메이션을 생략합니다. 모바일은 기존 사이트 정책에 맞춰 2px 카드 부유·느린 테두리 흐름·미세한 글자 밝기 변화를 유지하고 정지 버튼을 제공합니다. 탭·뒤로 가기 복귀 시 가시성을 다시 확인합니다. 숫자는 단색으로 표시해 텍스트 클리핑 지원 여부에 영향을 받지 않습니다.


## 셀럽 검색 정보

- 관리자에 저장된 셀럽 목록을 기준으로 홈의 초기 HTML에 이름·Instagram 아이디·프로필 링크·셀럽별 상품 링크를 렌더링합니다. 목록을 비우면 기본 계정을 되살리지 않습니다.

## 모바일 모션 재검증

375px 브라우저 에뮬레이션에서 `prefers-reduced-motion: reduce`를 실제로 켜고 카드와 테두리의 계산된 애니메이션 이름·재생 상태 및 650ms 간격의 프레임 변화를 확인했습니다. 일시정지 시 둘 다 `paused`로 전환됩니다. 이전 검증에서는 인스타라이브 밖으로 이동하면 모션이 정지했습니다. 이후 실제 휴대폰 정지 제보에 따라 모바일의 화면 밖 정지 조건을 제거했습니다. 실제 휴대폰 하드웨어 테스트와는 구분합니다.

헤더 아래 안내는 44px 높이를 유지하며 하트·스티커·작은 입자·연속 아래 화살표가 움직입니다. 모션 감소 환경에서도 완만하게 재생됩니다. 안내 클릭 후 바이럴 베스트 상단과 고정 헤더 하단이 모두 116px에 정렬되는 것을 확인했습니다. PC 본문 상단 여백은 기존 최대 70px에서 10~18px로 줄였습니다.

팔로워 표시 방어 회귀 검증: `tests/celeb-profile-cache.test.ts`에서 8시간 동안의 연속 실패, 인증 미설정 응답, 잘못된 숫자, 정상 복구·감소·0명, 다른 계정과의 분리, 최초 조회 실패를 검증합니다. 브라우저와 서버 모두 마지막 정상 수치를 보존하고 오래된 값에는 마지막 확인 표시를 유지합니다. `tests/instagram-cache.test.ts`와 API 테스트는 저장 데이터 검증·장기간 장애·저장소 장애·서버 재시작 및 토큰 교체 뒤 계정별 복원을 검증합니다.

2026-09-28 재검증: 모바일 375px에서 화면 감지 실패 상태(`is-offscreen`, 진입 클래스 없음)와 모션 감소 설정을 함께 재현해도 800ms 간격의 카드 이동과 테두리 색 위치가 변합니다. 정지 버튼은 두 모션 모두 `paused`로 전환합니다. 모바일 글자 웨이브는 개별 translate/rotate 속성 대신 transform을 사용합니다. 물리적인 iPhone·Android·인앱 브라우저 테스트를 대신한 결과는 아닙니다.

같은 날 Meta 직접 조회가 오류 190(토큰 만료)을 반환했습니다. 반환된 만료 시각은 2026-09-28 10:00 KST입니다. 인증 오류를 공통 토큰별로 5분간 재시도 제한하고, 새 토큰으로 교체하면 즉시 재검증합니다. 공개 응답에는 안전한 분류(`issue: authentication`)만 포함하고 Meta 원문이나 토큰을 노출하지 않습니다. 로컬 API는 화면과 동일한 공개 서버 셀럽 목록을 1분간 캐시해 사용하며, 새 등록 계정의 기본 목록 불일치 404를 수정했습니다. 명시적인 로컬 `INSTAGRAM_CELEB_ACCOUNTS` 설정은 우선합니다. 장기 토큰 교체가 완료되기 전까지 실제 수치 조회는 복구된 상태가 아닙니다.

운영에서 `issue: authentication`인 503과 Meta 디버거의 `유효: False`를 재확인했습니다. 브라우저도 인증 실패를 5분간 공유해 다른 셀럽·컴포넌트 재마운트의 중복 호출을 중단하고, 5분 뒤 다시 시도합니다. 이미 전송 중인 요청은 완료될 수 있습니다. 동일한 셀럽 목록을 새 배열로 받아도 조회 효과를 재시작하지 않습니다. `tests/celeb-story-client.test.ts`는 인증 장애 중 호출 억제·5분 뒤 복구·계정별 장애 분리·취소 처리를 검증합니다. 이는 호출 폭주 방지이며 인증 복구를 의미하지 않습니다.

## 장기 사용자 토큰 전환

현재 Business Discovery 공식 참조는 Facebook 사용자 토큰을 요구합니다. 일반 장기 사용자 토큰은 약 60일이며, 만료된 토큰은 연장할 수 없어 Meta 재인증이 먼저 필요합니다. 만료일 없는 페이지 토큰이 있다는 이유로 현재 API의 사용자 토큰과 임의로 교체하지 않습니다. 서버에서 기존 토큰을 반복 교환하는 작업을 무기한 자동 갱신이라고 보장하지 않습니다.

1. Meta 탐색기의 기존 앱·권한으로 유효한 사용자 토큰을 발급받아 `.env.local`에 저장합니다.
2. 같은 파일에 `META_APP_ID`, `META_APP_SECRET`을 설정합니다. 비밀값은 채팅·Git·브라우저 코드에 넣지 않습니다.
3. `npm run extend:instagram`은 앱 일치·권한·유효성을 확인하고 장기 토큰을 교환한 뒤, 만료일과 실제 Business Discovery 조회를 검증한 경우에만 `.env.local`의 토큰과 만료 시각을 교체합니다. 실패 시 기존 설정을 유지하며 비밀값은 출력하지 않습니다.
4. 운영 Netlify의 `INSTAGRAM_ACCESS_TOKEN`을 교체하고 재배포한 뒤 `npm run check:instagram`으로 모든 등록 계정을 검증합니다. 로컬 토큰 교체만으로 운영 환경은 바뀌지 않습니다.

2026-09-29 재점검: 기존 로컬 토큰은 Meta 직접 요청에서 오류 190/463을 반환했고, 만료 시각은 2026-09-28 13:00 KST였습니다. 운영 7명 역시 인증 실패 상태입니다. 새로운 토큰의 발급·장기 교환·운영 반영이 끝나기 전까지 인증 복구 완료로 간주하지 않습니다.

같은 작업에서 사용자 재인증 및 Meta 디버거의 확장으로 새 장기 사용자 토큰을 발급했습니다. Meta 재검증 결과 유효하며 만료 시각은 **2026-11-27 11:51:11 KST**입니다. 비밀값을 출력하지 않고 로컬 `.env.local`에 반영했고, 개발 서버 등록 7명 모두 `ready`와 실제 팔로워 수를 확인했습니다. 정상 스냅샷도 개발 서버 디스크에 저장했습니다. 운영 비밀 변수 교체·재배포 결과는 별도로 확인해야 합니다.
